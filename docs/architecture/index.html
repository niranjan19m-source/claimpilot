How ClaimPilot works

A LangGraph state machine with Claude at the reasoning steps and auditable code at the deciding steps. The LLM chooses what to investigate and interprets evidence. Rules turn evidence into scores. People sign off on denials and fraud.

Agent graph

1Intake

Reads the form, documents and photos. Extracts structured facts (Claude Haiku). Masks PII.

2Plan

Chooses investigation depth and tools, and states the hypotheses to test (Claude, structured output). Guardrails force the mandatory steps.

3Investigate

Tool-use loop: calls tools in parallel, reads results, adapts, records cited facts and findings. Bounded tool budget.

4Verify

Deterministic critic. Checks required evidence, valid citations, and that coverage reflects the latest facts. Sends gaps back.

5Decide

Explainable scoring: noisy-OR fraud score, points-based severity, coverage ledger, routing policy.

6Report

Cited triage report, handler brief and claimant letter (Claude).

7Gates

LangGraph interrupts: waits for missing documents (then re-plans) or for a human on SIU, denials or low confidence.

8Act

Creates the ticket, assigns by role, authority, region and caseload, sets the SLA, notifies, queues settlement.

Verify → Investigate loop when evidence is missing (max 2)Gates → Intake when documents arrive (full re-plan)State is check-pointed to SQLite: paused claims survive restarts

Claude decides

  • How deep to investigate, and why
  • Which tool next, and when to stop
  • What documents and photos actually say
  • Facts and findings, each citing evidence ids
  • Report, handler brief, claimant letter

Code decides

  • Coverage: every clause, every rupee
  • Fraud score: noisy-OR of flags, mandatory SIU indicators
  • Severity points and routing matrix
  • Handler selection and SLA
  • Rejects uncited findings and facts

People decide

  • Every SIU referral before action
  • Every coverage denial
  • Any decision below 60% agent confidence
  • Overrides are logged to the audit trail

Robustness & responsible AI

  • PII masking: phones, emails, PAN, Aadhaar and names become stable pseudonyms before any LLM call, so link analysis still works.
  • Graceful degradation: a failed tool lowers confidence rather than crashing the run. An LLM outage falls back to the rules plan.
  • Bounded autonomy: tool budget, verify-loop cap, recursion limit, and refusal fallbacks on the API.
  • Audit trail: every plan, tool call, finding, decision and human action is an immutable event.
  • Explainability: each fraud point maps to a flag, each flag to evidence, and each coverage decision to a clause.
  • Never accuses: claimant letters carry no fraud language. Indicators go to investigators only.
